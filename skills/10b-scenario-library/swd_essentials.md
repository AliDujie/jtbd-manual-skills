# SWD (Storytelling with Data) Skill — 精简后备知识

> **用途**：本文件是 scenario-library 随包发布的 SWD 方法论字典，提供报告展现所需的关键方法。基于 Cole Nussbaumer Knaflic《Storytelling with Data》。
>
> **优先级**：报告设计与叙事构造优先查本字典；字典未覆盖的展现判断按本Skill内置规范工作。
>
> **注意**：scenario-library 中的叙事结构（模块一"全局判断+矛盾与破局"）已根据场景库报告的特点做了专门调整，不应被 SWD 的通用三幕结构覆盖。本文件中的叙事方法论仅供参考理解，不替代 scenario-library 的现有写法。

## 1. SWD 六课核心方法论

| 课程 | 核心问题 | 关键行动 | 在场景库报告中的应用 |
|------|---------|---------|---------------------|
| 1. 理解上下文 | 受众是谁？需要他们做什么？ | 明确受众→定义行动号召→提炼核心观点 | 报告开头明确"这份报告给谁看、看了要做什么" |
| 2. 选择合适展示 | 什么图表最容易被受众理解？ | 用决策树选图→避免饼图/3D/双Y轴 | 柱状图、表格、四象限图的选择 |
| 3. 消除杂乱 | 哪些元素不增加信息价值？ | 去边框→去网格→去冗余→留白 | CSS中去除不必要的装饰元素 |
| 4. 聚焦注意力 | 受众应该先看什么？ | 灰色基底+强调色→视觉层次 | 柱状图颜色策略、数值高亮规则 |
| 5. 像设计师思考 | 是否专业且易理解？ | 可供性+可访问性+美学 | 字号规范、字重三级体系 |
| 6. 讲述故事 | 数据讲了什么故事？ | 叙事结构→行动标题→先结论后证据 | 倒金字塔结构、结论前置 |

**黄金法则**：
- 探索性 ≠ 解释性——只展示"珍珠"不展示"牡蛎"（只呈现有价值的发现，不呈现分析过程）
- 柱状图必须从零基线开始
- 颜色稀疏使用——不是越多越好
- 每张图必须有标题和轴标题
- 直接标注数据，不用独立图例

## 2. 图表选择决策树

```
你要展示什么？
├── 1-2 个关键数字 → 简单文本（大字号 + 支撑文字）
│   例：Hero区的"共485条场景 / 8位用户"
│
├── 精确数值查找 → 表格 / 热力图
│   例：四力对比表、行动路线图表格
│
├── 两变量关系 → 散点图
│   例：模块五的辅助气泡图（密度 vs 净推动力）
│
├── 时间趋势
│   ├── 两个时间点 → 坡度图
│   └── 多个时间点 → 折线图
│
├── 分类数据
│   ├── 类别名长 / 类别 > 5 → 水平柱状图 ⭐首选
│   │   例：模块二场景分层柱状图
│   ├── 类别名短 → 垂直柱状图
│   └── 起点 + 增减 + 终点 → 瀑布图
│
├── 部分与整体 → 100% 堆叠水平柱状图
│
└── 永远避免
    ├── 饼图 → 替代：水平柱状图
    ├── 3D 图表 → 替代：2D 版本
    └── 双 Y 轴 → 替代：拆分为两张图 / 直接标注
```

## 3. 注意力引导核心原则

**原则1：灰色基底 + 单一强调色**
- 所有非重点数据使用灰色（#94a3b8 或 #cbd5e1）
- 只用一种强调色突出最重要的信息
- 适用于一级主题≤5个的柱状图（scenario-library 的方案A）

**原则2：多色有主次**（当分类多时的变体）
- 所有主题使用不同颜色但有主次区分
- TOP N 个用 opacity:1，其余用 opacity:0.6-0.7
- 适用于一级主题≥6个的柱状图（scenario-library 的方案B）

**原则3：数值着色规则**
- 负面/危险 → 红色（#dc2626）：负净推动力、高焦虑
- 中性/警示 → 黄色（#d97706）：中等水平
- 正面/安全 → 绿色（#059669）：正净推动力
- 用颜色传递判断，让读者不看文字也能感知好坏

**原则4：视觉层次三级**
- 第一层（粗体/大字/强调色）：标题、核心结论、关键数字
- 第二层（常规/正文色）：分析正文、解释说明
- 第三层（细体/浅色/小字）：用户原声、辅助数据、脚注

**原则5：眼睛测试**
- 完成图表后，后退一步，眯眼看——你的眼睛最先被吸引到哪里？
- 如果最先看到的不是你想让读者看到的信息，说明注意力引导失败

## 4. 设计评估三维度

| 维度 | 定义 | 场景库报告中的检查点 |
|------|------|---------------------|
| **可供性(Affordance)** | 设计元素是否让人一看就知道怎么用？ | 可点击的标题是否看起来像链接？折叠的details是否有明显的展开提示？ |
| **可访问性(Accessibility)** | 所有读者都能看懂吗？ | 字号是否≥16px？颜色对比度是否足够？表格在手机上是否可读？ |
| **美学(Aesthetics)** | 是否专业、一致、不杂乱？ | 对齐是否整齐？留白是否恰当？颜色是否克制（非彩虹色）？风格是否全篇一致？ |

**快速检查清单**（阶段5交付前使用）：
- [ ] 每张图/表是否有标题？
- [ ] 每个坐标轴是否有标注？
- [ ] 颜色使用是否克制（非装饰性用色）？
- [ ] 对齐是否整齐（检查左对齐/居中是否一致）？
- [ ] 最重要的信息是否一眼就能看到？
- [ ] 读者能否在10秒内找到核心结论？

## 5. 五维度诊断评分体系

每维度 20 分，总分 100 分。用于报告交付前的设计质量自检。

| 维度 | 评分项（每项5分） | 不合格表现 |
|------|-------------------|-----------|
| 上下文(20) | 受众明确 / 行动号召清晰 / 核心观点可见 / 数据支撑故事 | 不知道给谁看、看了不知道该做什么 |
| 视觉选择(20) | 图表类型合适 / 无饼图3D / 零基线 / 逻辑排序 | 用了饼图、3D、数据无排序 |
| 杂乱度(20) | 无多余元素 / 无对角文本 / 留白恰当 / 无冗余 | 边框网格密布、装饰元素多 |
| 注意力(20) | 用了前注意属性 / 颜色稀疏 / 视觉层次清晰 / 眼睛测试通过 | 彩虹色、无主次、看不出重点 |
| 设计叙事(20) | 文字充分 / 对齐美学 / 叙事结构 / 行动标题 | 无标题、无结论、纯数据堆砌 |

**评级标准**：90+ 卓越 ｜ 70-89 良好 ｜ 50-69 需改进 ｜ <50 需重做
