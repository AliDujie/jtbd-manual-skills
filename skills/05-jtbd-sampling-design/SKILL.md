# 样本设计与招募

## 触发场景

- 假设已拆好，进入采样阶段
- 招募中遇到困难（响应率低、爽约率高、找到假样本）
- 项目预算变化，需要重新调整样本规模
- 团队 leader 审核采样计划

## 核心能力

### 能力一：假设到样本数的映射

对六板斧的每一板斧，推荐样本数：

| 板斧 | 推荐样本数 | 原因 |
|---|---|---|
| 真需求 | 4-6 人 | 痛点验证，样本可少 |
| 目标人群 | 3-4 人/组 × N 组 | 需要人群对比 |
| 迁移可能 | 8-10 人 | 四力模型需要分布 |
| 形态可信 | 5-7 人 | 新概念测试 |
| 竞争差异 | 3-4 人（辅以竞品桌面研究） | 混合方法 |
| 算账 | 5-8 人（辅以问卷） | 定性+定量结合 |

总样本量 = 各板斧样本数之和（可复用重叠人群）。

### 能力二：三种采样逻辑匹配

- **探索型**：多样性优先，覆盖不同情境（8-12 人，情境差异明显）
- **验证型**：同质性优先，代表同一挣扎（6-8 人，特征清晰）
- **对比型**：分组对齐，做人群/情境差异分析（每组 5-6 人 × 2-3 组）

### 能力三：双筛选招募标准

生成招募问卷的两层筛选：

- **正筛选（Must-Have）**：符合目标人群的必要条件（角色、频次、行为）
- **反筛选（Screen-Out）**：排除干扰因素（相关行业从业者、近期已参与其他访谈、极端案例）

标准输出格式：可直接交给招募供应商的表格。

### 能力四：样本失败补救策略

针对四类常见失败提供补救：

- **响应率低**：拓宽渠道 / 提高报酬 / 简化筛选
- **爽约率高**：短信提醒 / 提前 24h 确认 / 备份候选人池
- **发现选错人**：中途换人 / 结论标注局限 / 补充招募
- **样本量不够**：用问卷补 + 二手数据补 + 明确报告局限性

### 能力五：饱和度判断

给出"访到第几个人可以停"的三条经验线：

- 相邻两位受访者的新增信息 < 15% → 接近饱和
- 关键假设已有 3 位受访者交叉验证 → 该假设可停
- 时间 / 预算硬约束到期 → 必须停并标注局限

## 依赖底层 skill

- **jtbd-hypothesis-decompose**（关卡 1）：接收假设作为输入

## 输出形态

一份"采样计划书"，包含：
1. 样本总量 + 每假设分配
2. 采样逻辑说明
3. 招募问卷（正筛选+反筛选）
4. 招募渠道建议
5. 饱和度判断标准
6. 失败补救预案

## 与其他 skill 的关系

- **前置**：jtbd-hypothesis-decompose（关卡 1）
- **后置**：jtbd-interview-guide（关卡 3）根据样本设计访谈提纲

## 常见踩坑（本 skill 内置校验）

- 样本数过多导致预算爆炸（超过 15 人的项目务必分批灰度）
- 招募筛选过严导致找不到人（正筛选条件建议不超过 4 条）
- 忽略反筛选导致找到"专业受访者"（本 skill 强制生成反筛选题）
