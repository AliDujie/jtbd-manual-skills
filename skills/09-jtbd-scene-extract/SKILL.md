# JTBD 场景库两遍式抽取

输入是单场访谈的转录文本（已由录音转成文字并完成必要纠错）。本技能完成“访谈 → 27列主表 → 8个ODI富化字段 → 35列合并表”的完整抽取与质量审校。

## 使用与依赖

先完整通读用户提供的访谈，理解前后修正、用户背景和行为，再抽取。默认OTA内容范围；其他行业先确定互斥维度，同项目沿用。不要因环境里有历史项目就替用户启动它。

执行前读取 [详细字段、理论、示例及五轮审校模板](references/scene-spec.md)。该文件保留字段定义与审校模板；下面的校准规则优先于其中的历史阈值或冲突表述。不把参考中的示例当真人数据。

唯一的机器校验实现是本目录 [validate.py](validate.py)，不要从旧快照或参考文档复制另一份。只依赖Python标准库，兼容 Python 3.9。没有Python时可人工逐项审校，但必须声明没有运行机器校验。

## 工作流

1. 通读全文，识别真实经历、被访者主动表达、访谈者引导验证和假设性回答。没有现场依据时标为待核，不替用户推定。
2. 第一遍抽27列主表，保留用户档案、情境、进步、当前方案、四力、情绪、引文、改进方向与质量分。一个场景一个意思，描述通常不超过80字；缺时间或人物关系不编造。数量由原文独立单元决定，不设凑数门槛；但单场明显低于常规区间（60 分钟访谈 30 条以下）时，回原文复查是否漏抽，而不是为凑数拆条。
3. 第二遍基于主表补8个ODI字段；信息不足必须回访谈核查，禁止把“以主表为输入”理解为不能回原文。单用户分区的富化展示表是“序号+8字段”共9列。
4. 单用户分区内用序号合并。跨用户须用完整用户ID+序号；同用户多次访谈使用不同序号范围或独立访谈分区，不能截掉ID尾缀合并人。合并前查一对一、重复键、孤立键与行数；不能仅按各自从1开始的序号连接。
5. 完成三轮递进质量自检（粗筛/精筛/终审），另做矛盾性和系统性审校，保留每轮真实变更与原文定位。使用已建证据矩阵减少重复搜读，但每条判断须回到原文，不声称同源复读等于独立验证。
6. 运行脚本、处理错误与审校警报，再交付。Markdown不一定能在所有Excel环境自动分列；需要Excel时实际生成xlsx并核对列数、行数和内容，不把改扩展名当转换。

每阶段保存完整行及接续序号。长表按内部批次写文件、合并校验，用户不承担“继续”操作；不可故意让输出自然截断，也不可用“同上”省字段。

## 字段契约

主表27列，顺序固定：

序号、用户ID、用户档案、内容范围、是否出境游、情境标签、进步阶段、用户具体场景、进步陈述、当前主要方案、曾尝试或放弃的方案、是否补偿行为、补偿行为描述、切换触发点、爽点、痛点、情绪状态、推力P、拉力L、焦虑A、焦虑子类型、惯性I、惯性子类型、关键原话、改进方向、场景总分、质量分明细。

尾部8列：

Outcome Statement、Job Map阶段、Job维度、创新信号强度、创新信号类型、竞争关系、付费意愿信号、频次信号。

第二遍在单用户分区展示时为“序号+8字段”，实际9列；跨用户中间表还需带用户ID。合并只保留一次连接键，最终35列。表头可带规范中的括号枚举，但名称、顺序不得漂移。

版本区别：旧表是27+6=33列；现行是27+8=35列，新增「创新信号类型」「竞争关系」两个标签列。嵌入旧模块的26+6=32不是同一契约，需人工逐字段映射。未测重要度/满意度时，ODI富化不能被称为已经计算ODI机会分。

## 校准规则（优先适用）

### 证据与未知

- 原话只能来自原文，允许必要断句/纠错，新增背景用方括号；评分说明须与引文区分，不把分析文字伪装成用户原话。保留原文定位，不能为“语义单一”删掉反证或限定。
- 进步可以是功能结果、情感状态或身份变化；不得把产品功能直接当进步，也不得强行把仅有功能证据的材料拔高成“成为什么样的人”。模板“帮我…让我能够…”可用，不要求编出身份转变。
- 四力、情绪、频次、付费意愿及标签有充分证据才填写。未知不是“无/否/0/最低分”，也不能用“未提及”掩盖没读原文。必填项不足就保留空值，提交缺口清单及草稿，不能为了通过脚本而补造。
- “是否补偿行为=是”须有具体自创/组合/非预期使用行为；普通打电话或看差评不自动是补偿。没有充分信息不自动记否。补偿表明用户在解决问题，但不等于新品类需求、规模或额外付费已获验证。
- 付费意愿“是”需要实际额外付费或明确愿付证据；已经遭受损失不等于愿付费。未提频次填未提及，不按经验猜测。
- 不用方案是任务未获满足或没有雇用合适方案，不把所有自救都归不用方案；仍雇用替代方案时可为间接竞争。竞争关系“无”仅表示已核该场景没有相应关系，信息不足留空草稿。

### 档案与枚举

档案列共 11 项，用 10 个分号分隔，缺项保留空位置：姓名、所属人群、年龄、年收入/消费力、职业、婚姻状况、是否有娃、是否高频商旅、旅行主要同行人、年旅行频次、主要目的地。历史档案若确有额外字段，要保留并明确映射，不删真实信息或凭位置猜含义。同用户多场档案变化先核时间，不机械抹平。

进步阶段只能想象/搜索/使用/实现；“决定购买”属于搜索，完成付款或实际体验属于使用。焦虑/惯性子类型是选择/使用/空；“财务风险”“平台习惯”不能仅凭词面自动映射。

四力是1–5整数，语义为推力/拉力/焦虑/惯性；不能混成旧PPAI。平均净力 `(P+L)/2-(A+I)/2` 与总和净力 `(P+L)-(A+I)` 相差两倍，分析时明写量尺，不沿用另一量尺阈值。

情绪写1–2个 `标签[1–5]`，英文逗号分隔；转折按时间顺序，不是无依据的心理诊断。是否出境游仅OTA且已知时填是/否，其他行业或未知留空。

### 评分与审校

总分是七维得分之和，范围0–100，并非每条都应等于100。唯一明细格式：

```text
完整度:A/15,精准度:B/15,颗粒度:C/15,进步洞察度:D/20,情绪深度:E/10,四力量清晰度:F/10,方案价值度:G/15
```

A–G须非负整数，各自不超过分母，加总等于场景总分。场景描述、引文、方案都须回原文和现实约束检查；四力的1–5是分析者编码而非用户测量。

单场单用户N≥20时，≥85分超过30%或≥90分超过10%触发人工复审警报；N<20不套配额。不得只为满足分布强制降分。只有评分证据确实不符标准才调整，并记录依据。

OS须中文方向动词+度量项+对象（可带情境）；机器仅做最小语法检查，度量项可操作性和语义单一性仍由人审。其余枚举和创新强度1↔类型无的对应沿用详细规范；强度和分类都未知时留空，而不是互相编造以求自洽。

## 补偿行为与清洗

补偿行为必须具有具体的组合工具、自创方案或非预期使用证据。字段“否”或缺少描述不能算已确认补偿；但空值也不能自动当真实“否”。“否，我直接打电话”等语句应检查完整上下文，不能靠前缀字符串替代语义判断。

保留脏值原文与行号，输出问题清单再修正；不把未知改成0、无或否：

- OS若只是Job Map阶段/Job维度标签，或缺方向、度量项、对象，回查原文。最低语法长度由校验器统一，不以长度直接判断洞察好坏。
- Job Map、Job维度、创新强度/类型、竞争关系、付费意愿、频次按字段契约的枚举核对。非法值先报错，不静默转换为“无”。
- P/L/A/I非1–5整数时不能直接纳入聚合；缺证据留空并说明，不用最低分或全样本平均值填补。
- 四力、情绪与标签是有证据的分析编码，不是由模型凭常识测量出的事实。

## 人工审校清单

人工必须检查：补偿行为漏抽、业务术语混淆、主动/被动状态误标、跨用户引文串行，以及原文覆盖与重复拆分。没有被访者或访谈者现场信息时，主动/被动状态保持待核。反例不能为叙事整齐而删掉。

## 校验和安全迁移

以下路径均相对本技能目录；从其他目录执行时用脚本绝对路径。

```bash
python3 validate.py 场景库.md
python3 validate.py 证据不足草稿.md --draft
python3 validate.py 场景库.md --fix
python3 validate.py 旧33列.md --migrate-33
```

退出码与JSON：

- `0 / format_pass_needs_evidence_review`：严格格式通过，仍须证据及警报审校，不等于可直接用于决策。
- `1 / fail`：表结构、数值、必填、重复键等错误，修后重跑。读取、输出路径等错误也返回1。
- `2 / draft_not_deliverable`：草稿，必填缺项逐条列入missing，不可当严格交付通过。命令参数用错也返回2，但不产生草稿JSON。

脚本检查完整表头顺序、列数、原文件行号、复合键、必填、枚举、情绪强度、各维上限与加总、补偿字段相互一致、创新强度与类型；跳过围栏代码中的示例。每份输入使用相同处理阶段，不把主表和合并表混放成两份重复数据。

`--fix` 只按脚本内置阶段同义词表规范化明确写法，保存带正文的新文件并重验；不推断四力/子类型/用户身份、不改分数、不覆盖原文件或已有输出。剩余错误会继续返回1。

`--migrate-33` 按字段名映射，允许旧字段重排，但缺失/重复字段拒绝。新「创新信号类型」「竞争关系」留空，输出 `_35_draft.md`，正常迁移仍返回2。迁移不是内容富化或事实验证。

交付同时保留缺口、机器结果和人工复核记录。回归测试使用独立合成格式夹具，不把夹具分数写回研究知识库。
