# JTBD 场景库两遍式抽取与评估

从用户访谈原文中，基于 JTBD（Jobs To Be Done）理论框架精准抽取信息并构建颗粒度极细的场景库，同时对每条场景进行严苛的量化质量评估。适用于各行业用户研究与需求洞察，默认预设在线旅行平台（OTA）维度集。

## 本包内容

- `SKILL.md` — 技能主文件（使用与依赖、两遍式工作流、字段契约、校准规则）
- `validate.py` — 独立可运行的格式校验脚本（27/35 列自适应，只依赖 Python 标准库，兼容 Python 3.9+）
- `references/scene-spec.md` — 详细字段定义、理论与示例、五轮审校模板；主文件中的校准规则优先于其中的历史阈值或冲突表述

## 使用

把一场访谈录音原文交给支持长上下文的 AI Agent，并启用本技能。Agent 会：

1. 通读全文 → 生成 27 列主表
2. 基于已生成的表 → 补充 8 列 ODI 富化（含创新信号类型、竞争关系两个标签列）
3. 单用户分区内按序号合并；跨用户用完整用户ID+序号，合并为 35 列交付表
4. 执行五轮质量自检（3 轮循环 + 矛盾性 + 系统性）
5. 运行 validate.py（或等效自检）做格式合规校验

最终交付 35 列 Markdown 表格（可直接粘贴）；需要 Excel 时实际生成 xlsx 并核对列数、行数和内容——Markdown 不一定能在所有 Excel 环境自动分列。创新信号类型、竞争关系两列支持后续报告直接做占比/透视聚合。

### 单独跑格式校验

```bash
python3 validate.py scene_library.md          # 检查并输出违规报告
python3 validate.py scene_library.md --fix    # 规范化明确的阶段写法，输出 *_fixed.md
```

## 安装

把整个目录复制到本机 agent 工具的 skill 加载目录，目录名去掉 `09-` 前缀、与 `SKILL.md` 中 `name` 字段一致（即 `jtbd-scene-extract`），随后按所用工具的说明重载。
