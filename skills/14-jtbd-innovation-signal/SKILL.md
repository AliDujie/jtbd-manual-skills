# 创新信号识别与分级

## 触发场景

- 场景库和四力分析完成，进入创新洞察阶段
- 想从大量场景里挑出“值得追的机会”
- 已经识别出候选机会，但不知道该做新业务还是体验优化
- 机器跑出一堆 S 级，业务方问“凭什么”
- 机会清单要进立项会，需要能解释每一级的判断依据

## 这一步产出什么、往哪儿接

- **输入**：35 列富化场景库（含“创新信号类型”列）、四力分析与田字格结果
- **产出**：L2 信号画像表、S/A/B/C 机会清单、与田字格的一致性核对
- **报告怎么用**：正文只展开 S 级和 A 级，B/C 放附录；每个级别都要带判定依据和覆盖用户数
- **下游**：补偿行为交给 `jtbd-compensation-productize`（关卡 11）；S/A 级机会交给 `jtbd-ost-loop`（关卡 12）设计实验

## 核心能力

### 能力一：五种信号识别

对每条场景，判断属于哪一种信号，或标“无”：

| 类型 | 定义 | 强度对应 |
|---|---|---|
| 补偿行为 | 用户以非预期方式使用、组合工具或自创方案（最强信号） | 4-5 |
| 非消费 | 用户本可做但选择不做（“太麻烦就不弄了”） | 3-4 |
| 不满意使用 | 在用但持续抱怨 | 2-3 |
| 异常使用 | 使用频率或方式与设计预期不符 | 3-4 |
| 情境变化 | 新情境使旧方案失效 | 3-5 |
| 无 | 无明显不满或补偿 | 1 |

从 35 列场景库的“创新信号类型”列直读（富化时已预标注），不从访谈原文重判。原文用来核对标签，不用来重新起一套口径。

### 能力二：L2 级信号聚合

对每个 L2 主题，聚合五个数：

- **主导信号类型**：占比最高的那一类
- **信号叠加数**：同时出现了几种类型
- **非消费占比**：这个 L2 里非消费场景占多少。分母是该 L2 的场景数，不是全库场景数
- **强度均值**：该 L2 内信号强度的平均值
- **覆盖用户数**：按人去重，同一用户多条场景只算一次

五个数缺一个，分级就先别下。

### 能力三：S/A/B/C 四级分级

- **S 级**：三种以上信号叠加；非消费占比超过 30%；现有玩家做不了（不是没做）。三条同时成立，指向新产品或新业务线。一份报告通常只有 0 到 2 个
- **A 级**：两种以上信号叠加；日频或周频；难受程度高。指向当期重大功能升级
- **B 级**：一种信号；强度不低于 3.5。指向体验优化
- **C 级**：有信号，但覆盖用户少于 3 位，或强度分歧大。先持续监测，不急着立项

分级不是打分排名。叠加数、非消费占比、频次、强度各管一段，不能只看一个数。

### 能力四：与优先级田字格交叉校验

- **S 级**：应落在“立即行动”或“快速收割”
- **A 级**：主要在“立即行动”
- **B 级**：按密度和净推动力落到“立即行动”或“快速收割”
- **C 级**：通常落“观察等待”

对不上，先查两处：场景密度是不是算低了，净推动力是不是为负。查完还落不上，再回头重审分级判断依据。交叉校验是复查提示，不是判级依据。

### 能力五：人工先判二十条

机器跑全表之前，人先抽二十条带信号的场景，把“创新信号类型”和原文并排看。逐条问：

- 看到补偿行为，问他具体做了什么
- 看到非消费，问他是没做，还是做了但难受
- 看到情境变化，问换的是什么情境、什么时候换的
- 看到异常使用，问用法哪里偏离了设计

二十条判完，记录这批数据的标签偏差。比如访谈提纲里补偿行为问得深，补偿就会被多标；非消费问得浅，就会被漏标。这个偏差要在分析前写下来，不能等报告被质疑时才解释。

### 能力六：AI 跑全表，人做复核

自己判过二十条，机器能接四件事：

- 按 L2 聚合信号分布，算叠加数、非消费占比、强度均值和覆盖用户数
- 按判断依据分级
- 跟四力田字格结果对照，列出错位项
- 生成 S/A/B/C 机会清单

把下面这段贴进对话框，能先跑一版：

> 这是一份已经完成富化的 35 列场景库，每行一条场景。
> {粘贴场景库}
> 按 L2 聚合“创新信号类型”的分布：主导类型、出现几种类型、非消费占比、强度均值、覆盖用户数。
> 按判断依据分级：S 级为三种以上信号叠加、非消费占比超过 30%、现有玩家做不了；A 级为两种以上信号叠加、日或周频次、难受程度高；B 级为一种信号、强度不低于 3.5；C 级为有信号但覆盖用户少于 3 位或强度分歧大。
> 跟四力田字格结果对照：S 级应落在立即行动或快速收割，A 级主要在立即行动；对不上的单独列出来。
> 输出一张 Markdown 表：第一列是 L2，后面依次放信号分布、叠加数、非消费占比、覆盖用户、级别、判定依据、田字格象限、建议行动。
> 字段缺失标“缺失”，拿不准标“待复核”，不要替我拔高级别，没有 S 级就留空。

结果回来，人先看五处：

- 非消费占比的分母对不对。是占这个 L2 的场景，不是占全部场景
- 覆盖用户数是不是按人去重
- C 级有没有被硬抬成 B 级
- 田字格错位的两项，是密度算低了，还是净推动力为负
- 每个 S 级的“现有玩家做不了”，有没有真的查过竞品

机器答不了的那一问是：这个 S 级机会，今年该不该做。它不知道预算、人手和老板的优先级。

## 最小工作流

1. 确认场景库已富化“创新信号类型”列，未富化先升级
2. 抽二十条场景，人先判一遍，记录标签偏差
3. 按 L2 聚合五个数
4. 按四级判断依据分级，每个级别写判定依据
5. 跟四力田字格对照，列出错位项并复查
6. 生成 S/A/B/C 机会清单，带代表原话和覆盖用户数
7. 人工复核分母、去重、S 级数量、竞品判断
8. 把补偿行为交给产品化环节，把 S/A 级机会交给实验设计环节

## 20 分钟自检

挑一个你最想推的 L2，手算四个能独立核对的数（主导类型从这四个数里直接看得出来）：

1. 出现了几种信号
2. 非消费场景占这个 L2 的多少
3. 覆盖了几位用户
4. 强度均值是多少

四个数和你给的级别对不上，先改级别，别改数。算完再问一句：现有玩家是真的做不了，还是根本没做。这两句话差别很大。

## 输出形态

- **L2 信号画像表**：主题 / 主导信号 / 叠加数 / 非消费占比 / 强度均值 / 覆盖用户数
- **S/A/B/C 机会清单**：级别 / 判定依据 / 建议行动 / 代表原话 / 覆盖用户数
- **田字格一致性核对**：错位项 / 错位原因 / 复查结论
- **标签偏差记录**：哪类信号被多标、哪类被漏标、对分级的影响

## 边界与失效情境

- **信号标签不是事实**：预标注是入口。原文和标签冲突时，以原文为准并标“待复核”，不要为了省事直接信列
- **强度不是优先级**：强度 4.5 的场景很多，全堆到前面，看不出哪个能变成新业务。叠加数和非消费占比同样要过
- **S 级是稀有级别**：一份报告通常 0 到 2 个。一页出现 5 个 S，先怀疑评高了，不要先庆祝
- **30% 是经验阈值，不是统计显著性**：样本小或场景分类口径变化时，标“待验证”，不要拿它当硬结论
- **田字格错位不等于分级错**：可能是密度或净推动力算错了。先查那两个数，再重审判断依据
- **覆盖用户少于 3 位就停 C**：样本不够时，信号再强也只能监测，不能抬级立项
- **机器看不到访谈现场**：标签偏没偏、这个信号是不是用户真痛，要人回原文复核
- **分级不能替代取舍**：它回答“这是什么级别的机会”，不回答“今年做不做”

## 常见踩坑（本 skill 内置校验）

- **只按强度排序**：把强度当成唯一标准，忽略了叠加数和非消费占比
- **把不满意使用当最强信号**：用户抱怨得凶，不等于他会为解决方案付钱；补偿行为才是需求已经发生的证据
- **从原文重判**：每个人一套口径，最后合并不到一起。强制直读富化标签
- **S 级评多了**：判断依据没查竞品，或非消费占比不够，也给了 S
- **只报级别不报依据**：业务方问“凭什么”时答不上来，清单就失去作用
- **把补偿行为直接当产品机会**：信号识别只回答“哪里有活”，产品长什么样是下一关的事
