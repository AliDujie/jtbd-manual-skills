# 洞察质量把关

## 触发场景

- 报告洞察章节写完，交付前要把关
- 洞察句读起来“很对但没用”，业务方反馈“没有洞察”
- 团队成员的洞察停在“用户想要 X”
- 报告里数字、原话都有，但读完不知道下一步做什么
- 需要用 AI 批量审计洞察，但不想被它把废话写圆

## 这一步产出什么、往哪儿接

- **输入**：报告洞察章节初稿，每条洞察一段，带数据、用户原话、行动建议
- **产出**：洞察审计表（每条一行）、不合格洞察的返工建议、通过率
- **报告怎么用**：每条洞察按总-分-总写，建议后跟代价；审计表是交付前自检，不随报告发布
- **下游**：洞察过关后，进入创新信号识别（关卡 10）。洞察回答“这意味着什么”，创新信号回答“哪里藏着新机会”

## 核心能力

### 能力一：四种废话识别

- **正确的废话**：反过来问也成立，或者哪件事都适用（“用户体验有待改善”）
- **无佐证的判断**：没有数字、场景、原话（“这是最大痛点”）
- **无观点的综述**：列了事实，没说意味着什么（“访谈提到三个方面，其中保质期占 40%”）
- **学术化推演**：整页均值、模型、术语，不回答“下季度改哪”

命中任一，标出位置。四种都无，才进入深度检查。

### 能力二：五层 So What，一直问到行动

对每条结论连问“然后呢”，每问一次往下走一层：

- **层 1，数据**：一个数字或事实
- **层 2，现象**：这个数字背后发生了什么
- **层 3，原因**：为什么会这样
- **层 4，影响**：这件事带来什么后果
- **层 5，行动**：下一步做什么，要付什么代价

只走到层 2 是半成品。层 2 的回答听着完整，其实还没回答“所以呢”。

判定规则：

- 停在层 1 或层 2 → 不合格，补问
- 到层 3、层 4 但没有行动 → 半成品，补行动
- 到层 5，但行动写成“加强管理”“提升意识” → 仍不合格，具体到改什么、谁来做、付什么代价

示例（临期商品处理）：

- 层 1：38% 的受访店长在用自己的办法处理临期商品
- 层 2：纸质本、手机备忘录、门店微信群，每天自己记哪一批先到期
- 层 3：库存系统按商品管数量，不按批次管日期；折扣权限在区域经理手里，审批常常错过最佳处理时间
- 层 4：临期商品挤到最后 24 小时打折，折扣从 7 折降到 3 折；总部只看到损耗金额，看不到卡在哪一批
- 层 5：批次保质期做进库存视图，临期前 7 天提示，折扣建议给到店长；代价是收货多扫一次批次码，2 名工程师做 3 个月，区域经理放一部分折扣权限

### 能力三：三个特征，分清整章要求和逐条要求

- **立场鲜明的判断句**：敢说什么是主要的、什么是次要的。每条洞察都要过
- **至少一条反直觉发现**：跟业务方原本相信的不一样，且有数据支撑。整章至少一条，不要求每条都有
- **矛盾不回避**：两种说法同时成立时，解释为什么共存，给出边界解法。影响结论的矛盾，每条都要解释

判定规则：

- 没有判断句 → 返回重写第一句
- 整章没有反直觉发现 → 补一条；每条都硬找 → 也是问题
- 有矛盾未解释 → 标出矛盾，补解释；数据不足时标“待验证”，不要编解释

### 能力四：总-分-总结构

每条洞察按三段写：

- **总（结论）**：第一句直接给判断，不从“数据显示”“根据访谈”开头
- **分（佐证）**：1 到 2 个最典型的场景，必须带用户原话
- **总（决策含义）**：回到“所以下一步做什么”

任一段缺失 → 返工。原话不能替代判断，有原话但停在“用户希望”，仍然不是洞察。

### 能力五：代价必带

只有收益、没有代价的建议，业务方不会信，也没法拍板。建议后面跟一段代价，通常写四种：

- **研发成本**：几个人、几个月
- **短期负面影响**：可能损失什么、得罪谁
- **组织成本**：哪些部门要协同
- **不确定性**：可能失败的场景是什么

只写“做了会更好”，不写“要付什么代价” → 强制补。代价写到能拍板的程度，不是给不做找理由。

示例：

> “建议做批次管理”只是一句愿望。补上“2 名工程师做 3 个月，收货多扫一次码，区域经理放一部分折扣权限”，业务方才能当场判断做不做。

### 能力六：人工先改三条，AI 再跑全章

这套检查，机器能帮上忙，但头一遍得自己来。挑报告里最像洞察的三条，自己走一遍五层 So What，再按三个特征和总-分-总过一遍。走完这三条，你才知道机器交回来的东西，哪一条是真推到了行动，哪一条只是把“用户希望”换了个说法。没走过，机器标出“停在层 2”，你也判断不了它标得对不对。

自己改过，机器能先做四件事：

- 把每条结论按五层拆开，标出停在哪一层
- 扫四种废话，给出命中位置
- 检查判断句、反直觉发现、矛盾解释有没有
- 检查建议有没有写代价

把下面这段贴进对话框，能先跑一版：

> 这是一份 JTBD 报告的洞察章节，每条洞察一段。
> {粘贴洞察章节}
> 对每条洞察往下问五层 So What：数据、现象、原因、影响、行动，标出它停在哪一层。
> 标出四种废话：正确的废话、无佐证的判断、无观点的综述、学术化推演。
> 检查三个特征：有没有立场鲜明的判断句、整章有没有至少一条反直觉发现、有没有解释数据里的矛盾。
> 检查每条行动建议有没有写代价：研发成本、短期负面影响、组织成本、不确定性。
> 输出一张 Markdown 表，列有洞察编号、停在哪一层、命中的废话类型、缺哪个特征、代价是否完整。
> 不要替我把话写圆，缺什么就标什么。拿不准的标“待复核”。

初稿回来，判断还得人来做：

- 这条判断是不是数据支持的。机器只看到句子，看不到访谈现场
- 这个反直觉发现是不是真的反直觉，还是业务方早就知道
- 这个矛盾该不该解释，解释成什么。机器不懂业务约束
- 这个代价业务方能不能接受。机器不掌握你们手上的预算和人力

机器答不了的那一问是：这条洞察该不该写进报告。它能查结构，查不出这条判断的分量。

## 最小工作流

1. 通读洞察章节，标出所有“用户希望”“用户觉得”句式
2. 每条跑五层 So What，标出停在哪一层
3. 扫四种废话，记录命中位置
4. 检查三个特征：判断句逐条看，反直觉看整章，矛盾逐条看
5. 按总-分-总重写不合格的洞察，补用户原话
6. 给每条建议补四种代价
7. 做删除测试和反转测试，筛掉凑数的判断
8. 人工复核数据支撑、反直觉真伪、矛盾解释、代价可接受度
9. 洞察改完，同步检查摘要、图表、行动清单，别让旧结论留在别处

## 20 分钟自检

打开最近一份报告，从洞察章节里挑三条最像结论的，做两件事：

1. 走五层 So What，看它停在哪一层。没到行动层，补
2. 过三个特征——判断句和矛盾解释逐条看，反直觉发现看整章有没有。再看建议有没有代价

顺手再补两个自检问题：

- **删除测试**：把这条洞察删掉，报告会少什么？答不上来，它就是凑数的
- **反转测试**：把这条判断反过来写一遍。反面如果是一句没人会信的话，原句多半是空话；反面如果是业务方真会相信、但数据能推翻的判断，原句才有信息量

反转测试示例：

> 原句：“用户嘴上谈价格，真正卡住他的是这笔钱花得值不值。”
> 反面：“用户就是嫌贵，跟值不值无关。”这是一个有意义的判断，只是被数据推翻了，所以原句有信息量。

三条走完，不到一小时。一条大约 20 分钟，查出来的问题，就是最容易被业务方问住的地方。

## 输出形态

- 洞察审计表：洞察编号 / 停在哪一层 / 命中的废话类型 / 判断句有无 / 整章反直觉发现有无 / 矛盾解释 / 代价是否完整 / 结论（通过、返工、待复核）
- 不合格洞察的返工建议，指明缺的是哪一层、哪一类废话、哪一段结构、哪一种代价
- 通过率报告：本报告 N 条洞察中 K 条合格
- 改动清单：洞察改完后，摘要、图表、行动清单里跟着改的位置

## 边界与失效情境

- **五层是思考工具，不是报告模板**：报告里按总-分-总写，不必把五层逐层铺开；五层用来检查自己有没有停在半路
- **反直觉是整章要求，不是每条都要硬找**：一条都没有是问题，每条都硬找也是问题；反直觉必须能被数据证明，而且业务方原本真相信
- **矛盾不回避不等于所有矛盾都要展开**：只在矛盾影响结论时解释；数据不足时标“待验证”，不要编一个顺滑的解释
- **代价不是劝退**：写代价是为了让业务方拍板，不是给不做找理由；代价写不全，建议就不完整
- **删除测试和反转测试是过滤器，不是评分器**：描述性洞察反转后可能没有意义，标“待验证”，不要机械删除；两条测试都过，也不等于这条洞察一定值得写
- **机器看不到访谈现场**：它能查结构、查层级、查有没有代价，查不出判断的分量、反直觉的真伪、矛盾该不该解释
- **原话不能替代判断**：有原话但停在“用户希望”，仍然不是洞察；原话是佐证，不是结论
- **字段缺失要显形**：数据、原话、代价缺失时标“缺失”或“待复核”，不要默认补齐

## 常见踩坑（本 skill 内置校验）

- **把数据描述当洞察**：38% 是数据，不是结论；数字后面没有“所以呢”，就还停在层 1
- **有原话没判断**：每条都配了用户原话，读完了还是不知道下季度改什么
- **停在层 2 就交付**：把“用户在用自己的办法凑合”当成了结论，没走到原因、影响和行动
- **反直觉硬找**：为了显得有洞察，硬造一条“跟预期不一样”，证据撑不住，业务方一追问就露馅
- **把矛盾抹平**：两种说法都有，只挑符合自己论点的那一面写，把最值钱的线索删了
- **只讲收益不讲代价**：只写“做了会更好”，业务方不会信，也没法拍板
- **AI 把废话写圆**：让机器润色，它会把“用户希望”改成更顺的“用户希望”，结构没变，判断还是没有
- **洞察改完，别处没同步**：摘要、图表、行动清单还挂着旧结论，报告前后打架
