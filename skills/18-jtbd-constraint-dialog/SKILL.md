# 业务约束对话

## 触发场景

- 报告结论清楚，业务方回一句“这个季度不做”“方向不在主战场”
- 对方说“上游不给”“技术上做不到”“合规不允许”，结论落不了地
- 对方说“这个方向老张在负责”“跟我们部门的项目冲突”“出了事算谁的”
- 分不清对方是真做不了，还是不想做、不能现在做
- 报告要写进约束，团队不知道怎么表达才不显得在对抗

## 这一步产出什么、往哪儿接

- **输入**：研究结论、关键证据、业务方原话、当期战略目标、组织分工
- **产出**：约束分类表（类型/硬软/依据）、动作方归因与改写句、战略三栏、人情路径、报告表达策略
- **上游**：`jtbd-insight-adoption`（关卡 13）把结论推到人面前，撞上约束后进入本 skill
- **下游**：`jtbd-ai-forge`（关卡 15）处理 AI 分工与幻觉识别
- **回看**：长期议题要写清触发条件和回看时间，到点重新进入判断

## 核心能力

### 能力一：三类约束，先认硬软

先分清两件事。不做，是排期和取舍，这季度不做，下季度还能重新争一次资源。做不到，是能力够不着，再争也没用，得回头改结论。两者混在一起谈，结论就废了。

再问一句：**如果现在给足资源和时间，这件事能不能做？**

- **战略权重（硬约束）**：公司当期把资源压在哪里。识别信号是“不在主战场”“这季度只做 XX”“CEO 盯着另一个方向”。应对是接受当期不做，把结论记进长期议题，写清重启条件
- **供给能力（硬约束）**：上游规则、技术边界、合规要求不允许。识别信号是“上游不给”“技术上做不到”“合规不允许”。应对是不承诺能力交付，改做预期管理和信息透明
- **组织人情（软约束）**：这件事归谁管、动了谁的盘子。识别信号是“这个方向老张在负责”“跟我们部门的项目冲突”“出了事算谁的”。应对是绕行、借势、拆小

**组织人情不是面子。** 面子是结论踩到某个人的过去，要换说法；组织人情是这件事的归属和盘子，要换路径。两者都软，但不能用同一套办法。

诊断口径：

- 不能做，是供给能力
- 能做，但公司这季度不投，是战略权重
- 能做，公司也没说不做，但某个人或部门不让动，是组织人情

三类经常混在一起。先分清哪一类最难对付，不要指望一次全解决。

### 能力二：归因铁律，先认动作方

**动作方，就是这件事要发生，得由谁动手。**

用户对某项能力的不满，如果执行方是上游服务商、政策规则、市场结构，洞察的落点应是“预期管理”或“信息透明”，不是“产品没做”。

判断口径：

- 动作方是产品自身：归因给产品，可以推动能力建设
- 动作方是上游服务商：归因给“产品做预期管理”，不推动“要求上游改规则”
- 动作方是政策规则：归因给“产品做信息透明”，不推动“跟政策对抗”
- 动作方是市场结构：归因给“产品做预期管理或信息透明”，不推动“改变市场结构”

改写示例（连锁餐饮到货差异）：

原结论：“产品应强制供应商确认到货差异。”

动作方不是产品：供应商不是平台的客户，结算规则也是客户和供应商之间谈的，平台没有强制力。

改写为三件产品能控制的事：

- 采购员收货时，能看到这单供应商还没确认
- 月结前三天，系统列出未确认单据和涉及金额
- 供应商收到带链接的消息，不用注册登录，点一下就能确认；不点也不影响收货，只是采购员知道这笔有风险

这就是预期管理和信息透明。它不承诺能力，只承诺不让人蒙在鼓里。

另一半铁律：**动作方是产品自己，就不能拿“预期管理”当不做的理由。** 该做的功能不做，只写一句“让用户提前知道”，等于把产品该干的活说成了沟通问题。

### 能力三：战略权重，接受这一季不等于丢掉结论

撞上战略约束，不要继续在会上补数据。补得越多，越像在争输赢；排期问题谈成信任问题，下一次连约都约不上。

把结论拆成三栏：

- **当期能做**：不新增项目、不改上线时间、在现有页面上能接住的那一小块
- **下季候选**：写清启动条件。采纳率起不来、对账差异进了客户投诉前三，就启动
- **长期议题**：写清谁在什么时间、看到什么数就重启

长期议题这一栏最容易写废。只写一句“以后再说”，没有回看的人、没有触发条件，三个月后就没人记得。

### 能力四：组织人情，绕行、借势、拆小

- **绕行**：不跟归属争议硬碰，找已经在处理这件事的一线角色，把动作加进他的现有流程，不用为这件事单设一个岗位
- **借势**：借已经公开说出口的方向，不拿老板压人。借的是目标，不是某个人的权力
- **拆小**：只做不碰结算、不改流程的最小一块，先在一个客户、一个小范围跑两周，让投诉和工时看得见

边界：对方反对的要是合规红线、用户利益或者原则，那就超出了人情，属于硬约束。绕行只适用于归属和盘子，不适用于原则。

### 能力五：左墙右墙，只在撞墙时拿出来

- **左墙**：战略上非做不可的底线
- **右墙**：供给上绝对做不了的边界
- **中间**：能施力的空间

这是一个工具，不是每份报告的开场白。只在结论撞上硬约束、要讨论“还能做什么”时拿出来。每份报告都先划一遍墙，讨论会变成走流程。

撞上约束的结论，报告里有三种写法：

- **约束是背景**：开头写清边界，业务方就不会反复问“为什么不做”
- **有约束但有路径**：把中间空间的动作列出来，每条写清谁做、多久、做到什么程度
- **超越约束是长期议题**：写进长期清单，带上触发条件和回看时间，不占当期资源

三种写法可以用在同一份报告里，但每条结论只能选一种主写法。

### 能力六：研究员的位置，有判断不替人拍板

- **越位**：替业务方拍板。“这个季度应该砍掉 A、先做 B”越过了研究员的位置。战略、成本、组织不在用户研究的判断里
- **退位**：只交数据不谈判断。“数据就是这样，做不做你们定”看起来谦逊，实际把判断也交了出去
- **正确定位**：给有立场的用户视角，把决策权留给业务方

标准说法：

> 从用户视角看，A 的价值大于 B，原因是 X。但战略取舍不在我的判断里。我能给的是：在不动排期和成本的前提下，有三个动作能先接住一部分。

### 能力七：人工先判三条，AI 再扫全量

机器能帮你把约束清单扫一遍，但它标的约束类型能不能信，取决于你先自己判过几条。

挑三条最容易被挡回来的结论，逐条问三件事：动作方是谁，是哪种约束，如果只能改范围，改成什么？

三条判完，机器能接四件事：

- 扫一遍结论，标出把供给侧问题写成“产品没做”的句子
- 按业务方原话分三类约束，标硬软，写出依据
- 给每条撞约束的结论推荐一种报告写法
- 起草三条追问，用来分清“做不到”和“不做”

下面这段，填上材料就能跑：

> 下面是研究报告的结论清单，每条一句，后面附业务方原话和这季度的目标。
> {把结论和原话贴在这里}
> 逐条判断动作方：产品自身、上游服务商、政策规则、市场结构。动作方不是产品自身的，标“供给侧”，并改写成“预期管理”或“信息透明”方向。
> 根据业务方原话判断约束类型：战略权重、供给能力、组织人情。标硬约束或软约束，写出依据；判断不了标“待确认”。
> 对每条撞约束的结论，从三种表达策略里选一种：约束是背景、有约束但有路径、超越约束是长期议题。说明理由。
> 给三条会上要问的追问，用来分清“做不到”和“不做”。
> 最后用 Markdown 表格收尾，列依次是：结论、动作方、约束类型、硬软、表达策略、改写句、待确认。
> 不要替我判断组织关系，也不要替我挑借势的对象；拿不准的标“待确认”。

拿到结果，四处要盯：

- 动作方是不是指到了具体的上游、政策或部门，不是笼统的“外部”
- 硬软判断有没有业务方原话撑着，不是机器猜的
- 改写句有没有偷偷承诺能力交付
- 表达策略是不是这次会议能定的，不是自说自话

机器给不了的，是谁真正有否决权、这个约束这季度会不会松动、某人的反对是原则还是盘子。这些情况机器都不知道，也不该由它定。

## 最小工作流

1. 记下业务方原话，先别急着改结论
2. 问“如果现在给足资源和时间，这件事能不能做”，分三类约束
3. 认动作方：产品、上游、政策还是市场
4. 供给侧问题改写成预期管理或信息透明；产品自身的问题不拿预期管理挡
5. 战略约束拆三栏，写清重启条件；人情约束找绕行、借势、拆小的路径
6. 每条结论选一种报告写法，只选一种
7. 用左墙右墙检查“还能做什么”，只在撞硬约束时用
8. 把判断压成一段有立场、有边界的话，决策权留给业务方
9. 长期议题写清回看人、触发条件、回看时间

## 20 分钟自检

翻出最近一份报告，挑五条“用户希望……”的结论，做三件事：

1. **问动作方**：要满足这条，谁来动手？产品、上游、政策，还是市场？
2. **分约束**：判断依据是“给足资源和时间，这件事能不能做”——做不了的标供给（动作方一般也在产品之外），能做但这季度不投的标战略，能做也没说不投、只是某个人或部门不让动的标人情
3. **改写**：供给侧的，改成“预期管理”或“信息透明”；战略的，写进长期议题并加触发条件；人情的，写一条更小的路径

做完，把内容发给业务方。对方能说出“这条我们这季度能做”或者“这条确实做不了”，这条结论才算找到了边界。

- **约束分类表**：结论 / 业务方原话 / 约束类型 / 硬软 / 依据 / 待确认

- **战略三栏**：当期能做 / 下季候选（触发条件）/ 长期议题（回看人、触发条件、时间）
- **人情路径**：绕行对象 / 借势依据 / 拆小范围 / 原则边界
- **报告表达策略**：结论 / 选用的写法 / 理由
- **研究员话术**：判断句 / 边界句 / 能做的三个动作
- **AI 复核清单**：动作方、硬软依据、改写句、表达策略四项

## 边界与失效情境

- **三类约束不是三个筐**：同一句“做不了”可能叠着战略、供给和人情，先分清哪一类最难对付
- **战略约束不能靠补数据解决**：会上补得越多，越像在争输赢，排期问题会被谈成信任问题
- **供给约束不能承诺能力交付**：产品能做的是预期管理和信息透明，不是替上游改规则
- **预期管理不是万能挡箭牌**：动作方是产品自己，功能该做就得做
- **组织人情不能越过原则**：对方反对的是合规红线、用户利益或明确原则，那就不是人情，是硬约束
- **借势不是借权力**：借已经公开说出口的方向，不拿老板压人，不搞人身依附
- **左墙右墙不是总领框架**：只在撞硬约束时用，每份报告都划一遍墙，讨论会变成走流程
- **长期议题不能写废**：没有回看人、触发条件和时间，三个月后就没人记得
- **研究员不替业务方拍板**：给有立场的判断，把战略、成本、组织的取舍留给对方
- **机器不懂组织关系**：它能分类、改写、推荐写法，判断不了谁有否决权、谁的反对是原则还是盘子

## 常见踩坑（本 skill 内置校验）

- **把“不做”当“做不到”**：明明可以争资源，却替业务方把话说死。一听到“这季度排不上”就改结论，连“下季度什么条件能上”都没问
- **把“做不到”当“不做”**：硬逼产品承诺上游改规则、改结算。结论看起来很硬，落地时没人接
- **把供给侧问题归因给产品**：用户想要 X，但 X 的执行方是上游、政策或市场，报告写成“产品没做”
- **拿预期管理当挡箭牌**：产品自己能做的功能不做，改写成“让用户提前知道”
- **三类约束混着谈**：一会儿说战略，一会儿说人情，业务方不知道你到底要什么
- **左墙右墙当总领**：每份报告都先划墙，讨论程式化，业务方跳过图直接问“你到底想说什么”
- **越位或退位**：替业务方拍板，或者只交数据不谈判断，两种都让研究失去位置
- **长期议题没有主人**：只写“以后再说”，没有回看人、触发条件和时间
- **AI 输出直接拿去用**：机器分不清谁真正有否决权，也分不清反对是原则还是盘子
