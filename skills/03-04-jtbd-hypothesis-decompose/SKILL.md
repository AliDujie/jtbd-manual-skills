# 六板斧假设拆解

## 触发场景

- 业务方甩了一句话过来（"看看用户为什么流失"）
- 项目启动会前需要产出"研究框架"文档
- 中途发现研究方向模糊、假设不清、验证目标不明确
- 团队 leader 要 review 下属的假设拆解

## 核心能力

### 能力一：六板斧假设生成

输入业务方的原始一句话 + 项目背景，输出六个可证伪假设：

1. **真需求**（痛点强度=频率×后果×(1-替代满意度)）
2. **目标人群**（先假设锚点、再验证痛感和规模）
3. **迁移可能**（推力+拉力 vs 焦虑+惯性 的净推动力分布）
4. **形态可信**（L1-L4 自动化信任阶梯）
5. **竞争差异**（竞品是否覆盖 + 满意度）
6. **算账**（付费意愿 / 留存复购正向影响）

每个假设包含：主语（人群）、谓语（现象）、阈值（可测数值）、验证方法。

### 能力二：可证伪三特征校验

对每个生成的假设做校验：

- 有具体主语（哪个人群）？
- 有具体现象（哪个动作/情境）？
- 有可测阈值（多少比例/多少分/多少次）？

三特征缺一律返工。

### 能力三：决策路径预演

为每个假设生成"不成立时的三种可能决策"：

- 项目终止 / 缩量 / 延后 / 降级 / 差异化调整

帮业务方在启动前就看到"如果假设不成立，我要做什么决定"。

### 能力四：验证优先级排序

给六个假设排优先级——哪个先验、哪个后验、依据是什么。通常按"验证成本低 + 决策影响大"两个维度综合。

## 输出形态

一张 Markdown 表格 + 一段结构性说明：

```
| 板斧 | 假设 | 阈值 | 验证方法 | 不成立时的决策 | 优先级 |
```

## 与其他 skill 的关系

- **前置**：jtbd-boundary-check（关卡 0）确认适用后使用
- **后置**：jtbd-sampling-design（关卡 2）根据六个假设设计样本
- **平行**：jtbd-constraint-dialog（关卡 14）业务约束确认

## 常见踩坑（本 skill 内置校验）

- 假设太抽象没法测（"用户对新方案有兴趣"）→ 强制返工
- 六板斧机械凑数不适用当前项目 → 允许缺 1-2 板但要说明
- 拆完不跟业务方对齐直接开始排样本 → 输出中强制包含"下一步对齐动作"
