# 四力分析与优先级

## 触发场景

- 35 列场景库已完成 L1/L2 分层，进入分析、写报告阶段
- 业务方问“这么多主题，先做哪个”，需要把四力数字变成先后
- 四力已经算完，但报告里只有一个净推动力，说不清数字的构成
- 大雇用和小雇用、主动和被动、焦虑和惯性的子类型存在混算风险

## 这一步产出什么、往哪儿接

- **输入**：分层后的 35 列场景库，每行一条场景，带 L2 归属、四力分数、进步阶段、焦虑/惯性子类型。主动/被动不是 35 列里的字段，来自场景整理或访谈现场判断；没有这份判断的标“待复核”，不要默认按被动处理。
- **产出**：四力聚合表、田字格、象限清单、子类型诊断附录
- **报告怎么用**：四力表放在分析章节，逐行说明每个 L2 的推力和阻力；田字格回答先看哪个；加权说明列让业务方知道数字由哪类场景撑起来
- **下游**：洞察写作与机会排序。净推动力只回答“哪个主题更值得先看”，不替代成本、战略、排期这些立项判断

## 核心能力

### 能力一：四力聚合与净推动力四档

对每个 L2，先把场景的推力、拉力、焦虑、惯性聚成四个均值，再算净推动力：

> 净推动力 =（推力均值 + 拉力均值）÷ 2 −（焦虑均值 + 惯性均值）÷ 2

这是平均净推动力口径。同一批四力若用总和口径 `(P+L)-(A+I)`，数值是平均口径的两倍；报告里要写明用的是哪一种，阈值不能跨量尺套用。

推力、拉力是推着用户改变的力量，焦虑、惯性是拖住他的力量。大于 0，用户倾向改变；小于 0，倾向维持现状。按大小分四档：

- **① 大于 1.5，往前推。** 用户想改变，吸引力压过担忧，进入方案设计。
- **② 0.5 到 1.5，先降阻力。** 用户想变，阻力不小。补信任、降切换成本。
- **③ -0.5 到 0.5，先观望。** 推力和拉力，跟焦虑、惯性差不多。别主推，先做教育，或者等情境变化。
- **④ 小于 -0.5，分开看。** 担忧和惯性占了上风。密度高先化解，密度低先放着。

四档只是给数字一个说法，先看大小。真正容易看错的，是构成。

同样是净推动力等于 0，可能四项全高：推力 5、拉力 5、焦虑 5、惯性 5，用户痛并纠结着，有能量可以调动；也可能四项全低：都是 1 分，用户对这件事根本无所谓。一个值得深挖，一个不值得，报告里却很容易写成同一句“意愿一般，暂不优先”。

所以四力分析不能只报净推动力这一个数，四项均值得一起摆出来。看报告的人要先知道，这个主题是“想变但害怕”，还是“根本没感觉”。

净推动力过了 1.5，也先别急着下“切换意愿高”的结论。还有三条要同时满足：

- 推力和拉力都到 3.5 以上
- 焦虑和惯性都在 3 以下
- 覆盖用户至少有 5 位

三条都过，这句结论才敢写。缺一条，报告里就写清缺的是哪一条。

### 能力二：Big Hire 和 Little Hire 分开算

JTBD 里把用户决定要不要换掉旧方案的那一刻，叫 Big Hire，大雇用；换完之后，每一次使用还愿不愿意继续用，叫 Little Hire，小雇用。

同一个用户，对不同问题的打分不是一回事。拿记账软件举例：“要不要从旧软件迁走”是大雇用，用户可能打推力 5 分，现在的账太乱，实在受够了；“每笔记账时分类顺不顺手”是小雇用，他可能只打 2 分，还能用，就是麻烦点。两个分混在一起算，平均 3.5，看着像中等痛点，实际上一头是换软件的痛，一头是某个功能小改进的痛，性质完全不同。

分起来不难，场景库里有进步阶段这一列：

- 想象、搜索阶段，用户在考虑要不要换，归大雇用
- 使用、实现阶段，用户已经用上了，归小雇用

分开聚合，两组数据分别指向两个方向。大雇用的重心在推力和拉力，报告里对应获客、定位、切换理由；小雇用的重心在焦虑和惯性，对应留存、使用体验、为什么用着用着就放弃了。

一个 L2 里两种场景都有，就拆成两行算，不要为了表格整齐合成一行。

### 能力三：主动和被动，加权之后再进表

每条场景在整理时都该补上主动或被动的判断。主动的场景，是用户自己讲出来的，有情绪、有细节；被动的场景，是追问之后才点头，回答平，细节少。这个判断在整理场景时补上，不占 35 列的字段位，聚合时照用。

四力聚合时，两类不能按一个权重算：

- 主动场景权重 1.0
- 被动场景权重 0.5
- 现场判断拿不准的权重 0.7

四个维度用同一套权重，保证口径一致：

> 加权均值 = Σ（分数 × 权重）÷ Σ权重

不这么做的后果，报告里很常见。5 位主动挣扎的用户，配上 3 位被动认同的用户，一比一平均，被动认同会把推力均值抬起来。业务方看完，以为“痛点很普遍”，实际上真正想变的人没那么多。

所以四力表里要加一列加权说明，标出每个 L2 里主动、被动各几场。例如：

- L2 主题 A：净推动力 1.2，含 8 场主动、3 场被动，加权后置信度高
- L2 主题 B：净推动力 1.8，含 2 场主动、6 场被动，加权后实际强度约 0.8

两行摆在一起，业务方就明白了。B 的表面数字更高，但撑起它的大多是被动认同，不能直接跟 A 比。

### 能力四：焦虑和惯性，要问是哪一种

焦虑和惯性各有两种，混在一起看，均值会掩盖解法。

- **选择焦虑**（决策阶段）：用户还没定，担心“这个方案适合我吗，选错了怎么办”。解法是信任建设：评价、试用、担保退款
- **使用焦虑**（使用阶段）：人已经用上了，担心“会不会出问题，我控制得住吗”。解法是体验保障：客服、故障回滚、把操作简化
- **选择惯性**（沉没成本）：“旧方案里已经投了这么多，换掉可惜”。解法是降切换成本：迁移工具、数据导入、老用户优惠
- **使用惯性**（旧习惯）：“我习惯这么干了，改起来还要重新学”。解法是渐进迁移：新老功能并存、一步步引导

同样是焦虑均值 4，解法完全不同。不分子类型，报告只能写“焦虑偏高，建议降低焦虑”——这句话谁都会写，写完还是不知道做什么。

主表里，焦虑和惯性各有一列子类型。聚合到 L2 时，别只报一个均值，把两种各占多少也带上。哪一类占多数，解法就从哪一类下手。

### 能力五：摆进田字格，回答先做哪个

四力聚完，每个 L2 有了一个净推动力，也有了场景数。把它们摆到一个平面上：

- **横轴**：场景密度，也就是这个主题的场景数占全部场景的比例
- **纵轴**：净推动力均值

横轴的阈值，取所有 L2 场景密度的中位数：把每个 L2 的百分比从低到高排，取中间那个数。纵轴的阈值取 0。两条线把平面切成四块，看上去像汉字“田”，所以叫田字格。

横轴为什么不用绝对值？有人图省事，定“场景数超过 30 算高密度”。项目总共 200 条场景时，30 条占 15%；总共 500 条时，30 条只占 6%。同一个 30，在两个项目里不是一个意思。密度中位数把每个项目的 L2 分成上下两半，项目多大都成立。

- **① 右上，立即行动。** 密度高、净推动力为正。用户多、意愿强，先做，起步资源 40%
- **② 右下，定时炸弹。** 密度高、净推动力为负。用户多但阻力大，先化解，起步资源 30%
- **③ 左上，快速收割。** 密度低、净推动力为正。影响面小但阻力低，快做，起步资源 20%
- **④ 左下，观察等待。** 密度低、净推动力为负。先看着，暂不投入，起步资源 10%

右下这个“定时炸弹”最容易被误读成不做。别当成不做。用户多、阻力大，今天不动，明天就走。给它 30%，不是让它继续堆功能，是花力气把焦虑和惯性拆掉。

40%、30%、20%、10% 是起步配比，不是预算军令。战略新品可以把“立即行动”提到一半；维护期的老产品，“定时炸弹”该多分。格子排的是分析里的先后，真正批多少资源，还得过业务约束那一关。

场景库后来补的那 8 列，也能在格子上挂成第二层信息：

- 创新信号强度过 3.5 的标一下
- 付费意愿过四成的标一下
- 高频场景往前排

它们不改变象限位置，帮你在同一个象限里再分先后。

### 能力六：人工先算一个主题，AI 再跑全表

这套计算不难，难在每一步都藏着判断。头一遍别让机器跑全表。

挑一个 L2，把它名下十几条场景摊开。自己算四项均值，数主动、被动各几条，按权重再算一遍；再看看焦虑和惯性里哪一种占多数，最后在纸上点一个位置。半天不到，就一个主题。

算过这一遍，机器交回来，你一眼能看出它是把被动算成了主动，还是把大雇用和小雇用混进了一个均值。没算过，表格再整齐，也只能看个热闹。

自己算过一遍，再把全部 L2 交给机器。下面四样活，它都能先做一版：

- 四力聚合，按 L2 算四项加权均值和净推动力
- 分类，按进步阶段分大雇用和小雇用
- 子类型诊断，把焦虑、惯性按选择、使用分堆
- 田字格生成，按密度中位数和 0 画四象限，标出每个 L2

一段可以直接跑的 prompt：

> 做完分层的场景库，每条场景一行，带 L2 归属。
> {粘贴场景库}
> 聚合时按 L2 算四项均值：推力、拉力、焦虑、惯性。主动/被动的判断来自场景整理或现场记录：主动权重 1.0，被动 0.5，拿不准的 0.7，四个维度用同一套权重；没有这份判断的标“待复核”，不要猜。
> 按进步阶段分大雇用（想象、搜索）和小雇用（使用、实现），分开算均值和净推动力。
> 统计每个 L2 里焦虑、惯性的子类型条数。
> 按净推动力标出四档（大于 1.5 / 0.5 到 1.5 / -0.5 到 0.5 / 小于 -0.5）。
> 输出一张 Markdown 表，列有 L2、雇用类型（大雇用/小雇用）、场景数、场景密度（%）、四项加权均值、净推动力、四档、主动和被动各几场、子类型分布。
> 再按场景密度中位数和净推动力 0 画田字格，列出四个象限各有哪些 L2。
> 字段缺失的标“缺失”，不要猜；拿不准的标“待复核”。

表交回来，四件事还得人过一遍：

- 主动、被动的权重有没有贴错场景
- 大雇用、小雇用的分类抽几行看看合不合理
- 焦虑和惯性该往哪个方向解
- 资源比例怎么调

还有一问，机器接不住：这个负净推动力的主题，现在要不要动。它看不见你们下季度的排期，也不知道哪个方向是公司今年的重点。

## 最小工作流

1. 按 L2 聚合四项加权均值和净推动力，记下主动、被动各几场
2. 按进步阶段拆大雇用和小雇用，一个 L2 两种都有就拆两行，表里用雇用类型区分
3. 数焦虑、惯性的子类型条数，标出哪一类占多数
4. 按四档判断动作，同时看四项构成，别只看净推动力
5. 算场景密度（百分比），取中位数作横轴阈值，净推动力 0 作纵轴阈值，画田字格
6. 用创新信号、付费意愿、频次做同象限内的第二层排序
7. 人工复核权重、分类、解法方向和资源比例，再写进报告

## 20 分钟自检

拿最近一份四力分析，找一个净推动力在 -0.5 到 0.5 之间的 L2，回场景库把四项加权均值拉出来。

四项都高，它是“痛并纠结”，值得设计降阻力的动作；四项都低，是“无所谓”，先放下，别再给它排方案。顺手看一眼主动、被动各几场，别让被动认同占了多数。

## 输出形态

- 四力聚合表：L2 / 雇用类型（大雇用/小雇用） / 场景数 / 场景密度（%） / 四项加权均值 / 净推动力 / 四档 / 主动和被动各几场 / 子类型分布 / 加权说明 / 象限
- 田字格图或表，标出每个 L2 的位置
- 每个象限的 L2 清单与决策含义
- 焦虑/惯性子类型诊断附录
- “切换意愿高”的结论只在三条判断依据都过时写；缺哪条，报告里点明哪条

## 边界与失效情境

- **净推动力不是立项决定**：它不知道成本、战略和依赖关系，只能告诉你哪个主题更值得先看，不能替你决定批多少钱、什么时候做
- **不该平均的不能平均**：主动和被动混算，被动认同会抬高推力；大雇用和小雇用混算，换方案的痛会被日常使用的小麻烦拉平
- **均值会掩盖解法**：焦虑 4 分只说明高，不说明该做信任建设还是体验保障，必须回到子类型
- **中位数阈值也有适用边界**：L2 数量很少时（比如少于 4 个），中位数只能把两三个主题切开，象限区分度有限，把它当讨论起点，不要当排名结论
- **起步配比不是预算**：40/30/20/10 只排分析里的先后，真正的资源要过业务约束
- **ODI 叠加不改变象限**：创新信号、付费意愿、频次只在同一象限内再分先后，不能拿它们把主题从一个象限挪到另一个
- **字段缺失要显形**：主动/被动、子类型缺失时标“缺失”或“待复核”，不要默认按被动、无子类型处理

## 常见踩坑（本 skill 内置校验）

- **把净推动力当结论**：1.5 就批资源，-0.8 就砍掉，数字被用出了它担不起的分量
- **主动和被动一比一平均**：被动认同把推力抬起来，业务方误以为“痛点很普遍”
- **大雇用和小雇用混算**：换软件的痛和日常使用的小麻烦被拉平，报告看不出该往获客还是留存走
- **焦虑和惯性只看均值**：报告写“建议降低焦虑”，等于没写，回表里数子类型
- **横轴拿绝对场景数当阈值**：30 条在 200 条的项目里是 15%，在 500 条的项目里是 6%，换一个项目就失效
- **把 40/30/20/10 当预算军令**：这是起步配比，不是批资源的依据
- **用 ODI 叠加挪象限**：第二层信息只排同象限内的先后，不改变四力算出来的位置
